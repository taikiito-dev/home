## 持ち出せない道具になった

自分がサーバーを持とうとした始まりは、思想ではなく不便だった。

自作のAI作業環境「MulmoClaude」を、手元のパソコンの端末に入れた。動くようにはなった。ただしそれは入れた1台の中だけの話で、外出するとその環境には触れなくなる。持ち出せない道具になってしまった。

次に引っかかったのは、MulmoClaudeを入れる先が最初に入れたMacだけとは限らない、ということだった。**これだったら別に何でも入れるじゃん。** 最初の1台に縛られる理由は、どこにも無かった。

そこから調べていって行き着いたのが、**クラウド上のパソコンに入れる**という考えだ。手元の機械ではなく、ネットの向こう側にある1台にMulmoClaudeを置く。これが「自分のサーバーを持つ」の出発点になった。データ主権という言葉を自分の話として使うようになったのは、この後からだ。

[写真の移行](/ja/notes/google-photos-to-immich/)や[ファイルの移行](/ja/notes/google-drive-to-nextcloud/)など、このサイトの他のガイドはすべて「ImmichやNextcloudが動くサーバーが、自分の手元に既にある」という前提で書かれている。ターミナル(文字を打ち込んで操作する黒い画面)を開いたこともない人がいきなりあの記事を読んでも、何をどこから始めればいいのか分からないはずだ。並べてみて、そこが一番の土台なのに書いていないことに気づいた。この記事は、その土台の話をする。

もうひとつ先に書いておく。**このサイトのコマンドを書いたのはClaude(AnthropicのAIアシスタント)で、私は決める側をやった。** この分担にしたことで「どこにサーバーを置くか」という判断だけに集中できた。その分担の中身は、この記事の「自分がどうやってこの作業を進めているか」で説明する。

**この記事でやること** — 「持ち出せる1台」を手に入れるために、他のガイドが前提にしている「自分のサーバー」をゼロから用意する。ドメインを取り、VPS(レンタルサーバー)を借りてDockerを入れ、インターネットに公開して動作確認するところまでやる。手順は[ページ後半](#手順)にまとめた。

## そもそも「サーバー」とは何か

普段使っているパソコンやスマホは、使う時だけ電源を入れて、使い終わったら閉じたり寝かせたりする。**サーバーとは、それと逆で、24時間365日ずっと電源が入っていて、インターネットの向こう側からいつでもアクセスできる状態のコンピュータ**のことだ。

Google Photosも、Gmailも、実態は「Googleが管理する巨大なサーバー群」に自分のデータを預けて、そこに常時アクセスしている状態にすぎない。「データ主権を取り戻す」とは、この「常時アクセスできる置き場所」を、Google任せではなく自分の管理下に置き換える、ということだ。そのためには、自分の管理下にある「常時起動しているコンピュータ」、つまり自分のサーバーが要る。

## サーバーを持つ2つの道

サーバーを持つには、大きく2つの選び方がある。

**① レンタルサーバー(VPS)を借りる** — 月額数百円〜数千円で、どこかのデータセンターにあるコンピュータの一部を間借りする方式。AWS Lightsail、さくらのVPS、カゴヤ CLOUD VPSなどが有名どころ。自分で機械を持たなくていい代わりに、月額費用がずっとかかり続ける。

**② 自分の手元にあるPCを使う(自宅サーバー)** — 使っていない古いPCや、ゲーミングPCのような性能の高いPCを、24時間つけっぱなしにして使う方式。初期投資(電気代はかかる)以外の追加費用がかからない代わりに、電源やネット回線が落ちたらサービスも止まる、という自己責任になる。

自分が最初に選んだのは①だ。手元の1台から離れると使えなくなるのが出発点の不便だったので、「手元ではない場所にある1台」であることが条件だった(下の「決定1」)。その後②の自宅サーバーに切り替えている。この経緯は「決定2」に書いた。

## 自分がどうやってこの作業を進めているか

このサイトのガイドは、自分がターミナルに一つ一つコマンドを手打ちして進めたわけではない。実際には**Claudeに「こうしたい」と会話しながら指示を出し、実際のコマンド実行やファイル編集はClaude側にやってもらう**、という進め方をしている。つまり**コマンドを書く側がClaude、決める側が自分**という分担だ。使っているのはMulmoClaude(自分がGitHub上で公開している、Claudeを使ったAIアシスタントの土台)というソフトで、これ自体の成り立ちは[開発日誌](/ja/archive/)に書いている。

このMulmoClaude自体も、ここまでの話と同じ「自分のサーバー」の上で動いている。**最初はAWS Lightsail(レンタルサーバー)の上で動かしていたが、Immichの顔認識をGPUで速く処理したいという理由で自宅のゲーミングPC(GALLERIA)に切り替えた時、Nextcloud・VaultwardenといったほかのサービスもろともMulmoClaude自体も一緒にGALLERIA側へ引っ越した。** つまり今は、この文章を書いているClaude自身も含めて、全部が同じ自宅の1台のPCの上で動いている状態になっている。

なので、このサイトの文章の「自分がやった」は、実際には「Claudeに頼んで、Claudeが実行した」を指していることがほとんどだと理解しておいてもらえればと思う。何をどうするかの判断・決断は全部自分がしている。手を動かす側を任せたぶん、決める側の仕事にじっくり時間を使える分担になっている。

## 出てくる専門用語を一通り

ここから先のガイドで繰り返し出てくる言葉を、先にまとめて説明しておく。

- **ターミナル** — マウスでクリックする代わりに、文字でコマンド(命令文)を打ち込んでコンピュータを操作するための画面。最初は怖く見えるが、実態は「決まった呪文を決まった場所にコピー&ペーストするだけ」の作業がほとんどで、慣れの問題が大きい。
- **Docker(ドッカー)** / **docker-compose(ドッカーコンポーズ)** — サーバー上でソフトを動かすための仕組み。1つ1つのソフトを「コンテナ」という隔離された箱に入れて動かすので、複数のソフトを同じサーバーに入れてもお互いが干渉しにくい。`docker-compose`は、その箱をいくつか組み合わせて一括で起動・停止するための設定ファイルの書き方。
- **ドメイン** — `taikiito.com`のような、自分のサーバーにつける覚えやすい名前。年間数百円〜数千円で自分の名義で取得できる(自分はCloudflare Registrarで取得した)。
- **DNS** — 「`taikiito.com`というドメインは、実際にはどのサーバーを指すか」をインターネット全体に教えるための、住所録のような仕組み。ドメインを取得したら、DNSの設定でどのサーバーに繋げるかを指定する。
- **Cloudflare Tunnel(クラウドフレア・トンネル)** — 自宅のサーバーを、自宅のルーターの設定(ポート開放という、外から直接アクセスできる穴を開ける作業)をいじらずに、安全にインターネットへ公開するための仕組み。自分もこれを使っている(手順の[Step 4](#step-4-cloudflare-tunnelでサーバーを安全に公開する)参照)。

これらのソフト自体は、すべて無料(OSS、オープンソースソフトウェア = 誰でも無料で使える公開されたソフト)で使える。かかる費用は基本的に「サーバー代(自宅の場合は電気代のみ)」と「ドメイン代(年数百円〜)」だけだ。

## 決定1 — 手元のパソコンではなく、クラウド上の一台に置いた

**日付** 2026年9月13日(記事執筆時点。判断は記事より前)

**迷ったこと** MulmoClaudeをどこに置くか。手元のパソコンに入れた状態では、外出するとその環境に触れなくなっていた。

**採った案** **クラウド上のパソコンを1台用意して、そこに置く。**

**却下した案** 手元のパソコンに入れたまま使い続ける。

**なぜ却下したか** 入れた1台の中でしか使えないから。MulmoClaudeを入れる先がMacだけとは限らないと分かった時点で、最初の1台に置き続ける理由が無くなった。

**残った教訓** **「どの機械に入れるか」ではなく「どこに置けば常に届くか」で考えると、選択肢が一気に変わる。** 手元の機械を数えている限りこの発想は出てこなかった。

## 決定2 — レンタルサーバー(VPS)から、自宅のゲーミングPCに切り替えた

**日付** 2026年9月13日(記事執筆時点。切り替えは記事より前)

**迷ったこと** サーバーをどこに置くか。最初はAWS LightsailというVPSを使っていた。

**採った案** **自宅のゲーミングPC(GALLERIA)を24時間つけっぱなしの自宅サーバーにし、Nextcloud・Vaultwarden、そしてMulmoClaude自体も一緒に引っ越した。**

**却下した案** AWS Lightsail(VPS)を使い続ける。

**なぜ却下したか** 写真管理ソフト(Immich)の顔認識機能がGPU(画像処理用の高性能な部品)を使うと速く動くのに、一般的なVPSにはGPUオプションが無いか、あっても高額だったため。自宅のゲーミングPCには既にGPUが載っていたので、それをそのまま活用できるほうが合理的だった。加えて、VPSの月額費用も浮いた。

**後から見た当たり外れ** 切り替え自体は目的を果たしたが、タダではなかった。WindowsとLinux(WSL2)の両方の知識が必要になったり、再起動のたびにサービスが自動で立ち上がらない不具合に何度も遭遇したりと、一筋縄ではいかない場面が何度もあった(「正直な難易度感」参照)。

**残った教訓** **どちらが正解ということはない。** GPUを使う予定が無く、自宅に眠っているPCも無いなら、まずは安価なVPSを1つ借りるところから始めるほうが手軽だと思う。自分の場合はたまたま条件が噛み合って自宅サーバーを選んだ、という話として読んでほしい。

# 手順

ここから下は、VPS(レンタルサーバー)でサーバーを1台立てるところまでの手順で、**Claudeが書き、自分の環境で実行して結果を確かめたもの**だ。自分が最初にやった手順そのままになっている。**自宅サーバー(Windows + WSL2)は環境依存が強すぎて万人向けに書き起こせないと判断し、まずは誰でも同じように再現できるVPSの手順に絞った。** 自宅サーバーへの切り替えは、この記事の後半「自宅サーバーに切り替える場合」で触れる。

手順をここに置いておく理由は2つある。ひとつは、**作業の全体像と長さが先に分かる**こと。見てのとおり5段階で、初めてターミナルを触る場合でも1〜2時間の話だ。もうひとつは、**自分が使っているAIに「これと同じことをやりたい」と渡す材料になる**こと。ゼロから説明するより、動いた実例を見せたほうが早いし、あなたの環境と契約したVPSに合わせた形に直してくれる。

## Step 1: ドメインを取得する

まず自分のサーバーの「名前」になるドメインを取得する。自分は[Cloudflare](https://www.cloudflare.com/products/registrar/)のRegistrar(ドメイン登録サービス)を使った。理由は、相場より安い実費に近い価格で提供されていて、WHOIS(ドメイン所有者情報)を公開しないプライバシー保護もデフォルトで付いてくるため。ダッシュボードの「Register a Domain」から、空いているドメイン名を選んで購入するだけで完了する。年間数百円〜数千円ほど。

## Step 2: VPS(レンタルサーバー)を契約する

自分が最初に使ったのは**AWS Lightsail**、リージョンはシンガポール、OSはUbuntu(Linuxの一種)、**プランは月$7(メモリ1GB・2vCPU・SSD 40GB)**を選んだ。動画生成のような重い処理をする予定がなければ、この最小プランで十分動く。契約すると、そのサーバーの持ち主だけが入れる「IPアドレス」(サーバーの住所のようなもの)が発行される。

VPSは他にもさくらのVPS・カゴヤ CLOUD VPS・DigitalOcean・Vultrなど選択肢は多い。自分がAWSを選んだ決め手は、シンガポール在住で近いリージョンが使えたのと、後々AWSの他サービス(バックアップ等)との連携がしやすそうだったため——ただしこの用途では正直どれを選んでも大差ない。

## Step 3: ターミナルからサーバーに接続し、Dockerを入れる

契約すると、サーバーに接続するための「SSH鍵」(パスワードの代わりに使う、より安全な鍵ファイル)が発行される。ターミナル(黒い画面でコマンドを打ち込む操作)から、次のように接続する。

```bash
ssh -i 発行された鍵ファイル ubuntu@サーバーのIPアドレス
```

接続できたら、Docker公式が配布しているインストールスクリプトを実行する。これ1行で、Dockerと`docker compose`がまとめて入る。

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
```

(2行目は、`sudo`〈管理者権限で実行〉を毎回付けなくてもDockerコマンドが使えるようにするおまじない。一度ログアウトしてから入り直すと反映される。)

## Step 4: Cloudflare Tunnelでサーバーを安全に公開する

サーバーは立ったが、まだ`taikiito.com`のようなドメインからはアクセスできない。公開のやり方として**Claudeが提案したのがCloudflare Tunnel**で、ルーターのポート開放(外から直接アクセスできる穴を開ける設定)は使わない方式だ。ポート開放は誤って設定すると自宅のネットワーク全体が外部から丸見えになるのに対し、Tunnel方式ならルーター側の設定を一切変更せずに`https://`の自分のドメインで公開できる、という理由だった。自分の環境ではこの提案をそのまま採り、ルーターは触っていない。

取得したドメインをCloudflareのネームサーバーに切り替えた上で(Cloudflareのダッシュボードの指示通りに進めれば数クリックで終わる)、サーバー側で次を実行する。

```bash
# cloudflaredをインストール
curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared.deb

# Cloudflareアカウントと連携(ブラウザが開くのでログインする)
cloudflared tunnel login

# トンネルを作成(名前は自分で決める。ここでは仮に my-server)
cloudflared tunnel create my-server

# ドメインとトンネルを紐付ける
cloudflared tunnel route dns my-server app.example.com
```

最後に、どのURLへのアクセスをサーバー内のどのポートに転送するかを設定ファイル(`~/.cloudflared/config.yml`)に書く。

```yaml
tunnel: my-server
credentials-file: /home/ubuntu/.cloudflared/<トンネルID>.json

ingress:
  - hostname: app.example.com
    service: http://localhost:8080
  - service: http_status:404
```

再起動しても自動で動き続けるよう、サービス化しておく。

```bash
sudo cloudflared service install
```

ここまでできれば、あとはサーバー内の`localhost:8080`(上の設定例のポート番号)で何かソフトを動かせば、`https://app.example.com`からアクセスできるようになる。ルーターのポート開放(外から直接アクセスできる穴を開ける、事故ると危険な設定)を一切いじらずに済むのがこの方式の利点。

## Step 5: 動作確認

具体的に何かソフトを動かして確認したい場合は、このサイトの次のガイド([写真をGoogle PhotosからImmichに移す](/ja/notes/google-photos-to-immich/))がそのままStep 6以降の実例になる——`docker-compose.yml`を書いてImmichを起動し、上のingress設定のポート番号をImmichのポートに合わせれば、そのまま公開まで到達できる。

## 自宅サーバーに切り替える場合

自分は後になって、AWS Lightsail(VPS)から自宅のゲーミングPC(自宅サーバー)に切り替えた。理由は決定2に書いたとおり、GPUを使いたかったのと月額費用を浮かせたかったため。ただしこの切り替えは、Windows PCの中でLinuxを動かす「WSL2」という仕組みや、再起動時の自動起動設定など、環境固有のハマりどころが多く、万人向けの手順としてはまだ書き起こせていない。GPUを使う予定がなければ、上記のVPS構成のままで十分運用できる。自宅サーバーへの興味がある場合は、今後別記事として書く予定。

## 正直な難易度感

ここまで読んで「思ったより大変そう」と感じたなら、その感覚は正しい。自分の場合も、自宅サーバーへの切り替えではWindowsとLinux(WSL2)の両方の知識が必要になったり、再起動のたびにサービスが自動で立ち上がらない不具合に何度も遭遇したりと、一筋縄ではいかない場面が何度もあった。上記のVPS手順自体はそこまで難しくないが、初めてターミナルを触る場合は1〜2時間はかかると思っておいてほしい。

ただし、これは「一度整えてしまえば、あとはほぼ触らなくていい」類の作業でもある。土台さえできてしまえば、その後の[写真の移行](/ja/notes/google-photos-to-immich/)や[パスワードの移行](/ja/notes/1password-to-vaultwarden/)といった個別の作業は、ここまでの土台よりずっと軽い。
